Consumer-side

✓ Merge gate: required checks block every merge to main

Ruleset main-required-checks (active) requires ci (node 22) + ci (node 24) + install-smoke on the default branch, with strict up-to-date policy — a PR behind main must rebase and re-pass against the new head before it can land. Admin (you) can bypass for direct commits.

  • Agent PRs: agent-auto-merge.yml no longer merges immediately — it arms GitHub auto-merge (AGENT_PAT-authored so merge events still fire workflows); GitHub completes the merge only when required checks go green. Post-merge cascade (issue close, sibling re-kick) moved to the PR-closed event. (9792396)
  • Stale branches: agent-update-branch.yml pushes the rebase → checks re-run on current main → auto-merge fires. Loop is closed.
  • Cost: each merge invalidates sibling PRs' checks under strict policy, so agent waves merge serially-ish — more CI runs per wave on the self-hosted runner. If the runner is down, merges stop (loud) instead of landing unverified (silent).
