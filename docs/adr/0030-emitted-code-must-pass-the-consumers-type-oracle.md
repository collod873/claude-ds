# 0030 — Emitted code must pass the consumer's type oracle

Date: 2026-06-10
Status: Accepted
Relates to: ADR-0003 (completeness), ADR-0026 (structural bypass / hand-verify
showcases), ADR-0029 (empty migration range), PRD #529 (cross-version journey
testing), #537 (verify-gate ownership partition)

## Context

A heal run in Crewops (CLI v1.8.1) failed its own verify gate with 79 TS errors
— every one in a file headed `@generated by claude-ds — do not edit`. The
1976-test suite was green. PRD #529's defect register attributed this class to
"stale JSX showcases the consumer hand-wrote, ADR-0026 hand-verify territory."
Investigation disproved that for all 79:

- `audit --fix`'s `cva-variant-unrendered` rule extracts CVA axes **file-wide
  by regex** (`src/lib/drift/cva.ts`) and writes a meta example per uncovered
  value (`rules/cva-variant-unrendered.ts`). In multi-CVA files the axes belong
  to *internal sub-elements* (`comboboxTriggerVariants`, `dropZoneVariants`,
  `backdropVariants`), so the fixer wrote props the exported component never
  accepted: `<Combobox size="sm">`, `<DialogContent weight="10">`.
- Boolean axes (`invalid: { true:…, false:… }`) are emitted as the string
  `invalid: "true"`.
- An older fixer leaked the Tailwind `dark:` modifier out of a class string as
  a variant value (`tone: "dark"` in Crewops badge.tsx, commit `deafca4`).
  The parser is since fixed, but nothing validates *existing* examples, so the
  poisoned residue regenerates broken showcases forever.
- The showcase generator carries a "LATENT BUG (multi-CVA files)" comment
  (`generate-showcase-companion.ts:1319`) deferring the fix on the assumption
  that "every current consumer carries empty examples arrays" — an assumption
  `audit --fix` itself invalidates by populating examples. The mask and the
  unmasking ship in the same product, and no test pins the assumption.

Why the suite was blind: the ~60 generator integration tests and the fixer
tests assert **string content** of emitted code. A string assertion encodes the
generator's own beliefs back at it — if the generator wrongly believes
`size="sm"` is a valid Combobox prop, the test asserting the output contains
`size="sm"` passes for the same wrong reason. The only ground truth — does the
consumer's compiler accept this file against the real component — is consulted
for the first time at heal time, in a real consumer, by the verify gate. The
gate then has no remedy: the errors are in do-not-edit files, regeneration is
deterministic, and re-running cannot converge.

## Decision

**Any code path that writes TypeScript into a consumer — the showcase
generator, every drift-rule fixer, every Op that emits or rewrites `.ts`/
`.tsx` — is tested by compiling its output against the real component source.
A string assertion alone is an invalid test for emitted code.**

Four commitments make that hold:

1. **Compile-what-you-emit test layer.** Generator and fixer tests typecheck
   the emitted file in the fixture's tsconfig context. One shared in-memory
   `ts.LanguageService`/program per test file keeps the cost in seconds, not
   per-test tsc spawns. Existing string assertions stay (they localize
   failures); they just stop being sufficient.
2. **Variant truth comes from the component's prop surface, not file-wide
   regex.** CVA parsing becomes a per-component AST pass (the repair already
   named in the generator's latent-bug comment): each cva() call is attributed
   to the component that consumes it via `VariantProps`, boolean axes emit
   `{true}`/`{false}`, and values are checked against the exported prop type.
   Meta examples whose props the component rejects are a *fixable drift
   finding* (remove or repair the example) — not hand-verify, because claude-ds
   wrote them.
3. **Fixtures sample reality, not ideals.** At least one fixture atom carries
   the shapes that broke Crewops together: multiple cva() calls, a sub-element
   CVA, a boolean axis, populated meta examples, Tailwind modifier prefixes in
   class strings. Invariant tests cannot catch type-broken emission — only a
   compiler seeing realistic input can.
4. **Deferring a bug on a masking assumption requires a tripwire test.** A
   comment documenting "this is masked because X" must be accompanied by a test
   that fails when X stops holding. Recorded in
   `.sandcastle/CODING_STANDARDS.md`. The multi-CVA deferral is the cautionary
   instance: the assumption died silently the day `audit --fix` learned to
   populate examples.

A release-time canary — running the release candidate's heal against a fresh
clone of the real consumer (extending the #535 refresh script's role) — is the
last line, catching whatever the layers above still miss before npm publish. It
runs at release, not in CI, so `npm test` stays fast (PRD #529's budget
stands).

## Consequences

- The 79 Crewops errors are reclassified: claude-ds defect, not consumer debt.
  #537's verify-gate partition must route errors in `@generated` files to a
  "claude-ds defect" verdict (report a bug, offer to revert/stub the generated
  file) — never to "verify by hand," which asks the operator to edit files
  whose header forbids editing.
- ADR-0026 stands but narrows: hand-verify covers JSX-bearing examples the
  *consumer* authored. Files claude-ds generated are never hand-verify; if
  they don't compile, claude-ds is wrong.
- The generator's CVA cross-product expansion and the `cva-variant-unrendered`
  fixer are rewritten on the per-component AST pass; Crewops's 30-line `skip[]`
  workaround in badge.tsx becomes deletable.
- Test suite gains seconds (shared program, budget ~+10s alongside PRD #529's
  layers), and gains the property the product is actually sold on: what
  claude-ds writes, compiles.
